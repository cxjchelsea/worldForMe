# 传播、借用与结构相似

## 1. 关系与证据必须分离

本专题固定使用：

```text
relation_type
+
evidence_level
```

同时允许一对对象存在多个并列关系声明，但每条声明必须单独给证据等级。

## 2. 当前关系记录

### 《阿特拉哈西斯》洪水传统 → 《吉尔伽美什史诗》XI 洪水重写

- `relation_type`: `historical_transmission`
- `evidence_level`: `strongly_supported`
- `relation_type`: `structural_inheritance`
- `evidence_level`: `strongly_supported`
- 说明：两者处在同一美索不达米亚书写传统网络中，并共享高度具体的保存—洪水—登陆—祭祀链。具体版本、语言阶段与文学依赖仍应由未来美索不达米亚 QC1.1 专题细化。

### 美索不达米亚洪水传统 ↔ 《创世记》6–9

当前拆成两条而不是混写成一个值：

1. `relation_type`: `structural_similarity`
   - `evidence_level`: `documented`
   - 说明：成组结构可直接文本比较。
2. `relation_type`: `historical_transmission`

   - 说明：古代近东存在历史接触与中介传播可能，但 Pilot 不支持“《创世记》直接复制某一现存泥版”的强断言。

### 希腊—罗马丢卡利翁／皮拉 ↔ 近东保存—方舟型洪水叙事

- 说明：当前可以确认它们共享 R1–R3，但关键槽位差异明显；本 Pilot 不利用相似性自行推定传播链。

## 3. 为什么不能把 relation_type 写成数组里的混合短语

第一轮曾使用：

```text
structural_similarity + possible historical transmission context
```

Content Pass B 认为这种写法不够严格，因为它又把“关系是什么”和“证据支持到哪里”重新揉在一起。

以后统一采用独立 relation records：

```yaml
source: ...
target: ...
relation_type: structural_similarity
evidence_level: documented

source: ...
target: ...
relation_type: historical_transmission
evidence_level: possible
```

## 4. 禁止的简化表达

避免：

```text
“圣经洪水故事抄自吉尔伽美什”
“全球都有洪水故事，所以一定发生过一次全球洪水”
“两个故事都有船，所以存在传播”
```

必须改问：

```text
具体共享哪些结构？
来源文本分别是什么？
历史接触是否可建立？
有没有中介文本或语言链？
哪一条关系证据支持到什么等级？
```

## 5. Pilot 结论

Content Pass B 支持：

```text
一条 relation record
= 一个 relation_type
+ 一个 evidence_level
+ 一个证据说明
```

而不是在一个字段中同时塞入多种关系。
