# 核心功能、身份锚点与可变特征

## 1. 为什么 named archetype 需要 identity anchor

抽象原型可以由多个不同人物共同承担，但命名型原型必须解释：

> 人物经过大幅重写后，为什么仍然被识别为同一个文化名字？

因此 Pass B 将原先单层 `identity_anchor` 拆为：

```text
required_identity_anchors
+
supporting_identity_anchors
```

## 2. required_identity_anchors｜最低身份连续

当前两项：

- `solomon_sulayman_name_identity`：Solomon / 所罗门 / Sulayman 等命名连续；
- `davidic_israelite_royal_identity`：与大卫王族、以色列王者身份保持可识别连续。

这两项回答“是不是所罗门”这一最低身份问题。

若一个后世人物只有“非常聪明的王”这一功能，却没有所罗门／Sulayman 的命名与谱系身份，就只能先比较为智慧王类原型，不应直接归入所罗门 named archetype。

## 3. supporting_identity_anchors｜高稳定辨识特征

当前：

- `wisdom_reputation`

智慧声望贯穿主要接受层，辨识度很高，但它更接近身份连续的强支撑，而不是纯粹的“同一人”最低条件；其他传统中的匿名智慧王也可以具有类似功能。

## 4. core_functions｜跨传统稳定角色功能

Pass B 后调整为：

- `wise_king_and_judge`：王权与卓越智慧／判断结合；
- `divinely_authorized_kingship`：王权以神圣授权、先知王或类似形式获得超越普通政治权力的正当性；
- `extraordinary_knowledge_authority`：人物逐步成为智慧、特殊知识乃至隐藏／超自然知识的权威载体。

这里故意把原来的 `sacral_royal_authority` 泛化为 `divinely_authorized_kingship`，避免只套用某一传统的神圣王权语汇。

## 5. 为什么 `builder_and_centralizer` 降级

《列王纪》来源层中，所罗门与圣殿建造、中心化和大型王权工程关系极强；但 named archetype 的 core function 必须能跨主要接受传统保持稳定。

到了：

- 晚期古代驱魔／魔法传统；
- Quranic Sulayman；
- 中世纪—近代 Solomonic magic；

“圣殿建造者／中心化者”并不是每次调用都不可缺少。

因此改为：

```text
builder_and_centralizer
→ temple_builder_and_centralizer
→ variable_feature
```

这不是否定其来源重要性，而是区分：

```text
source-figure defining feature
≠ named-archetype cross-reception core function
```

## 6. variable_features｜接受史可变层

- `temple_builder_and_centralizer`
- `wealth_and_splendor`
- `queen_of_sheba_encounter`
- `literary_wisdom_authorship`
- `exorcist_or_magician`
- `command_over_spirits_or_jinn`
- `magic_ring`
- `imperial_world_king`

这些特征可以在某些传统中高度突出，甚至成为主要辨识点，但不要求全部同时出现。

## 7. named archetype 连续性公式

Pass B 后工作模型：

```text
required identity continuity
+
at least one stable core-function bundle
+
reception-specific variable features
=
named archetype continuity
```

因此：

- 只有名字、没有任何稳定人物功能 → 可能只是 name borrowing；
- 有类似智慧王功能、但不是 Solomon / Sulayman → 只能先做 functional similarity；
- 保持人物身份并系统重写功能 → `figure_rewriting`；
- 重讲某一整套来源故事 → 才可能是 `direct_adaptation`。
