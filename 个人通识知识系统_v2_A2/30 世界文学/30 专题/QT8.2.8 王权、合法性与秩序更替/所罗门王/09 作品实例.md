# 作品实例

## 1. 来源层

### 《列王纪》

- `work_role`: `defining_source_text`
- 主要功能：智慧、审判、圣殿、繁荣、国际声望、王权扩张及其张力
- `source_status`: `reference_topic`

来源层继续进入 `qt82_source_reference`，不与后世接受关系混用。

## 2. 原型化关键文本／接受节点

### Josephus, *Antiquities of the Jews* 8.42–49

用于核证：所罗门智慧在早期犹太接受中已经被扩展到驱魔／超自然知识领域。

```yaml
relation_type: explicit_reference
evidence_level: documented
```

若未来需要把“同一人物功能被系统扩展”独立数据化，应另建第二条 `figure_rewriting` 记录，不在这一条里合并 relation type。

### *Testament of Solomon*

Pass B 改判：

```yaml
relation_type: figure_rewriting
evidence_level: documented
```

理由：它不仅继续使用 Solomon 名字，还保留王者／神圣授权／知识权威，同时系统新增驱魔、控制恶魔、戒指／印章和建造工程等角色功能。

### 《古兰经》中的 Sulayman

Pass B 改判：

```yaml
relation_type: figure_rewriting
evidence_level: documented
```

理由：命名身份、王权与智慧仍可识别，但进入伊斯兰经典语境后，人物被重新组织为先知王，并获得对风、鸟、精灵等受神授权能力；示巴女王故事也进入新的经典结构。

### *Key of Solomon / Clavicula Salomonis* 传统

当前继续保留：

```yaml
relation_type: character_or_name_borrowing
evidence_level: documented
```

因为这里最稳定的作用之一，是以“Solomon”之名为仪式魔法与隐藏知识提供权威。若具体版本进一步形成完整人物叙事，再另评 `figure_rewriting`。

## 3. Pass B 证明了什么

这组数据现在能清楚区分：

```text
explicit_reference
→ 明确调用／扩展来源人物

character_or_name_borrowing
→ 人物名字主要作为权威标签

figure_rewriting
→ 同一人物身份持续，但角色功能与叙事系统被系统重写
```

所以 named archetype 的后世证据不需要被迫塞进“借名字”或“整套故事改编”二选一。

## 4. 数据层规则

正式作品实例继续使用共享 `qt82_work_reference`。

若同一作品未来需要表达第二种关系，必须新增另一条原子记录，不合并多个 relation_type。

> 当前两个历史文件名仍保留 `name-borrowing` 字样以避免破坏已有 Obsidian 链接；其 frontmatter 与正文已改为 `figure_rewriting`。后续若做集中兼容性重命名，可再统一处理文件名。
