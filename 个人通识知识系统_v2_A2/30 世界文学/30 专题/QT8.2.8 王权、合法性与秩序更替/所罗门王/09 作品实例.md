# 作品实例

## 1. 来源层

### 《列王纪》

- `work_role`: `defining_source_text`
- 主要功能：智慧、审判、圣殿、繁荣、国际声望、王权扩张及其张力
- `source_status`: `reference_topic`

## 2. 原型化关键文本／接受节点

### Josephus, *Antiquities of the Jews* 8.42–49

用于核证：所罗门智慧在早期犹太接受中已经被扩展到驱魔／超自然知识领域。

当前工作关系：

```yaml
relation_type: explicit_reference
evidence_level: documented
```

### *Testament of Solomon*

用于核证：所罗门被重写成以神授权物控制、审问恶魔并把这种权能与建造工程结合的魔法王。

当前工作关系：

```yaml
relation_type: character_or_name_borrowing
evidence_level: documented
```

但这一关系词只能表示“继续使用同一命名人物”；它无法充分表达“同一人物被系统重写”，因此 Pilot B.1 提出 `figure_rewriting` 作为共享 schema 候选。

### 《古兰经》中的 Sulayman

用于核证：所罗门进入伊斯兰经典语境后，王权、智慧、先知身份与对风／精灵／鸟类等受神授权能力被重新组合。

当前工作关系：

```yaml
relation_type: character_or_name_borrowing
evidence_level: documented
```

同样建议未来由 `figure_rewriting` 更准确表达。

### *Key of Solomon / Clavicula Salomonis* 传统

用于核证：到中世纪—近代秘传传统，“Solomon”已经成为仪式魔法与隐藏知识的权威名称。

当前工作关系：

```yaml
relation_type: character_or_name_borrowing
evidence_level: documented
```

## 3. 为什么这些实例足以作为 Pass A

它们覆盖四种不同的身份漂移：

```text
来源王者
→ 超自然智慧
→ 魔法／驱魔王
→ 新宗教经典中的先知王
→ 秘传知识权威名字
```

因此能够测试 named archetype 的核心问题：**名字连续时，角色功能可以变化到什么程度，仍然保持同一个文化原型的可识别性？**

## 4. 数据层规则

来源层进入 `qt82_source_reference`；后续接受进入 `qt82_work_reference`。

同一文本若未来需要表达第二种关系，必须另建原子记录，不合并多个 relation_type。
