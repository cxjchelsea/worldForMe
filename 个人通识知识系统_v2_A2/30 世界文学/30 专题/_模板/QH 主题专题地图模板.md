# QH 主题专题地图模板

> 适用范围：Q 轴中的 **QH 主题与人类问题**叶节点。  
> 目标：在不继续膨胀全局 taxonomy 的前提下，把一个稳定的人类问题展开成可阅读、可比较、可维护的专题知识结构。

## 0. QH 专题的基本原则

QH 不回答“这是什么类型的故事”，而回答：

> **这批作品共同在追问什么人类问题；这个问题由哪些经验、关系、冲突与机制构成，又怎样在不同文学传统中变化？**

建立 QH 专题时遵守以下规则：

1. **一个专题必须有一个中心问题，而不是一组关键词。**
2. **先定义边界，再收作品。**“出现某元素”不等于“以该问题为核心”。
3. **全局坐标停在既定叶节点。**专题内部的问题群、阶段、机制、主体位置默认都不是新的 `QH*.x` 坐标。
4. **允许交叉，不追求互斥。**QH 是多值 facet；专题之间的重叠通过边界说明和桥接关系处理。
5. **不在 QH 内重建 T / R / M / G / QT。**时间、地域传统、思潮、形式、类型只作为比较维度，不能取代本专题自己的问题结构。
6. **不强制时间分期。**只有当“问题如何变化”确实具有历史解释力时，才建立历史纵轴。
7. **不强制地域平铺。**只有当不同传统对同一问题形成稳定差异时，才单独建立跨传统比较。
8. **内部结构以问题为第一维。**通常先建立 4–8 个稳定问题群，再按需要增加机制、尺度、历史或比较维度。
9. **作品实体唯一保留在 `40 作品/`。**专题只通过 stable topic ID 与 `.base` 投影作品。
10. **结构成熟后再冻结字段。**不要为了模板整齐预建空目录、空维度或无证据的关系。

```text
QHxx [节点名]/
├─ 00 [专题名].md
├─ 01 [专题名].canvas
├─ 02 [专题名]结构.base
├─ 03 [专题名]作品.base
├─ 10 结构/
│  ├─ 01 定义与边界.md
│  ├─ 02 核心问题地图.md
│  ├─ 03 经验尺度与作用机制.md
│  ├─ 04 跨时间、传统与形式比较.md
│  └─ 05 阅读路线.md
├─ 11 核心问题/
│  ├─ 01 [问题群A].md
│  ├─ 02 [问题群B].md
│  └─ ...
├─ 12 机制与变体/                  # 可选；只有存在稳定第二维时建立
│  ├─ 01 [机制/变体A].md
│  └─ ...
└─ _source/
   └─ [专题名]书单_原始版.md
```

### 与既有专题的兼容

- 已成熟的 QH6、QH7 不因本模板机械改目录名；它们已有稳定的 `11 细分`、`12 核心问题` / `12 记忆机制`，继续保留。
- 新专题优先使用上面的统一骨架，但某个主题如果确实需要第三维，可以像成熟的 T / R / M 专题一样新增 `13 .../`。
- “是否新增一层”的判断标准不是对称，而是：**这一维是否解释了作品之间稳定、可复用的差异。**

## 2. `00 [专题名].md` 首页模板

复制下列结构后替换方括号内容；stable ID 一旦投入作品数据后不要随意修改。

```yaml
---
id: WL-TOPIC-[STABLE-ID]
type: literature_topic_map
name: [专题名]
primary_anchor: WL-QH[节点号]
anchor_mode: leaf
topic_role: direct
structure_status: draft
work_database: "[[03 [专题名]作品.base]]"
structure_database: "[[02 [专题名]结构.base]]"
source_archive: "[[_source/[专题名]书单_原始版.md]]"
---
```

正文采用以下顺序：

```markdown
# [专题名]

> 路径：世界文学 → Q轴 → QH 主题与人类问题 → [父域，如有] → **[叶节点 / 专题名]**

## 1. 专题定位

先写“本专题不是什么”，再写“本专题真正研究什么”。

至少明确：
- 什么条件下作品进入专题；
- 什么情况只是背景、元素或邻近主题，不足以进入；
- 与最容易混淆的 1–3 个 QH / QT / M / R / T 专题怎样区分。

## 2. 核心问题

> **用一句可以跨时代、跨地区继续追问的问题定义整个专题。**

再拆成 4–8 个稳定子问题。子问题必须能用于比较多部作品，而不是作品剧情摘要。

## 3. 专题内部地图

- [[01 [专题名].canvas|[专题名] Canvas]]：只显示已有文件支持的认知关系。
- [[02 [专题名]结构.base|[专题名]结构数据库]]：动态查看正式知识节点。
- [[03 [专题名]作品.base|[专题名]作品数据库]]：从 `40 作品/` 投影专题作品。

## 4. 核心结构

- [[10 结构/01 定义与边界|定义与边界]]
- [[10 结构/02 核心问题地图|核心问题地图]]
- [[10 结构/03 经验尺度与作用机制|经验尺度与作用机制]]
- [[10 结构/04 跨时间、传统与形式比较|跨时间、传统与形式比较]]
- [[10 结构/05 阅读路线|阅读路线]]

## 5. 核心问题群

进入 `11 核心问题/`。

每个问题群回答：
1. 它具体追问什么；
2. 它与相邻问题群的边界；
3. 常见主体位置 / 关系结构 / 冲突；
4. 哪些作品最能建立直觉；
5. 它怎样连接其他 QH 主题。

## 6. 第二维：机制、尺度、历史或变体（按需）

只有确有解释力时建立 `12 .../`。

可选第二维包括：
- **经验尺度**：自我 → 亲密关系 → 家庭 → 共同体 → 制度 → 历史 / 超越；
- **作用机制**：压抑、规训、排斥、记忆、传递、选择、失序、救赎等；
- **主体位置**：行动者、受害者、旁观者、幸存者、继承者、局外人等；
- **历史变化**：同一问题在不同时期怎样改变；
- **跨传统变体**：不同文学传统怎样组织同一问题。

不要为了目录对称同时建立全部维度。

## 7. 跨轴比较

本节只用于校正视野，不把其他轴复制进 QH：
- T：这个问题在历史上怎样变化？
- R：不同文学传统怎样理解它？
- M：哪些思潮改变了问题的表达方式？
- G：诗歌、戏剧、小说、非虚构怎样改变问题的可表达性？
- QT：不同叙事类型怎样包装或放大这个问题？

## 8. 与其他专题的关系

只写有明确语义的桥：
- → [邻近 QH]：交叉点是什么，边界又在哪里；
- → [QT]：主题问题与故事类型如何区分；
- → [T / R / M]：何种历史、传统或美学条件改变了本主题。

不因“可能有关”就画边。

## 9. 阅读路线

路线围绕“理解问题”而不是“扫完书单”。推荐：

基础锚点
→ 两到三种不同回答
→ 一组边界案例
→ 跨传统 / 跨时代比较
→ 进入复杂机制与交叉主题

具体路线放入 [[10 结构/05 阅读路线|阅读路线]]。

## 数据职责

- `00`：专题认知入口，不维护动态作品数量。
- `01 Canvas`：只表达已经有文件证据支持的关系。
- `02 结构.base`：专题知识节点动态视图。
- `03 作品.base`：`40 作品/` 的专题投影。
- `10 结构/`：边界、核心模型、比较方法与阅读方法。
- `11 核心问题/`：QH 专题最稳定的第一内部维度。
- `12 .../`：按需建立的第二维，不默认存在。
- `40 作品/`：唯一作品实体；`topics` 使用本专题 stable ID。
- `_source/`：原始资料与重构前快照，不承担正式数据库职责。
```

## 3. 五个固定结构文件应该写什么

### `10 结构/01 定义与边界.md`

必须回答三个问题：

1. **纳入条件**：什么情况下主题是不可替代的核心问题？
2. **排除条件**：什么情况下只是剧情元素、时代背景或类型惯例？
3. **邻域边界**：最容易与哪些 QH / QT 专题混淆，如何判断主次？

推荐使用“如果把该问题拿掉，作品的主要冲突或意义结构是否会发生根本变化”作为第一判断测试。

### `10 结构/02 核心问题地图.md`

把主题拆成 4–8 个可复用问题群。好的问题群应该：

- 可以覆盖多个时代、多个传统；
- 能让作品之间发生比较；
- 彼此有边界但允许交叉；
- 不是人物、地点、事件或关键词枚举。

### `10 结构/03 经验尺度与作用机制.md`

回答“这个主题怎样作用于人”。优先观察：

```text
主体内部
→ 人际 / 亲密关系
→ 家庭与代际
→ 群体与共同体
→ 制度与社会结构
→ 历史记忆 / 终极价值
```

不是每个主题都需要覆盖全部尺度；只保留实际存在的层级。

### `10 结构/04 跨时间、传统与形式比较.md`

这里负责调用 T / R / M / G / QT 作为比较坐标，但不复制这些轴的 taxonomy。

至少问：

- 问题本身是否发生历史转义？
- 不同传统是否给出不同的主体位置或价值判断？
- 不同形式是否改变了谁能说话、什么能被表现？
- 某种类型是否会系统性放大某类冲突？

### `10 结构/05 阅读路线.md`

阅读路线至少分三层：

- **骨架阅读**：少量作品建立问题直觉；
- **比较阅读**：选择彼此答案明显不同的作品；
- **扩展阅读**：进入边缘案例、跨传统、跨形式或复杂交叉主题。

优先控制“功能覆盖”，不要追求作品数量最大化。

## 4. 作品数据库最低规则

`03 [专题名]作品.base` 最低只依赖：

- `topics`：stable topic ID 精确匹配；
- `read_status`：阅读状态；
- 作品页已有的 T / R / M / G / Q 坐标。

当专题结构稳定后，可增加 **1 个专题专属问题维度字段**，例如：

```text
[slug]_dimensions
```

必要时再增加：

```text
[slug]_priority
```

不要一开始就为每个内部概念建立字段。只有需要稳定筛选、比较或 Base 展示的维度才进入作品元数据，其余知识留在 Markdown。

---

## 5. Canvas 规则

QH Canvas 推荐围绕“问题结构”组织，而不是围绕书名堆节点：

```text
中心问题
├─ 核心问题群
│  ├─ 代表作品
│  └─ 相邻问题群
├─ 经验尺度 / 作用机制
├─ 必要的历史或传统变化
└─ 跨专题桥接
```

Canvas 边只表达专题文件中已经建立的关系，不根据视觉接近、共同关键词或作品共现自动推断。

---

## 6. 叶节点是否适合独立成专题的检查表

同时满足大部分条件时，才建立独立 QH 专题：

- 能用一句稳定问题定义，而不是只能列关键词；
- 有清楚的纳入 / 排除边界；
- 至少能形成 4 个左右可比较的问题入口，或一个同等强度的内部模型；
- 有跨时代或跨传统的作品支持，而不是只依附一个作家 / 一个类型；
- 与邻近专题虽有交叉，但拥有独立解释任务；
- 能形成一条功能明确的核心阅读路线；
- 内部结构已经足够丰富，继续拆成全局子节点反而会造成坐标膨胀。

如果达不到这些条件，优先保留为专题内部问题标签，而不是预建空的全局 QH 节点。

---

## 7. 完成标准

一个 QH 专题达到“结构完成”至少应具备：

- [ ] `00` 有明确专题定位和一句核心问题；
- [ ] 有稳定的纳入 / 排除边界；
- [ ] `10 结构/` 五个核心文件成立；
- [ ] `11 核心问题/` 已形成主题自身的第一维；
- [ ] 第二维只在确有解释力时建立；
- [ ] 至少存在一条跨 QH 或跨轴边界说明；
- [ ] 作品通过 stable topic ID 投影，不复制实体；
- [ ] 阅读路线按认知功能组织，不是简单按名气排序；
- [ ] Canvas 不制造无文件依据的关系；
- [ ] 没有为了形式对称而新增空节点、空字段或空目录。

> 最终标准：读完专题后，应该能够回答“文学围绕这个问题提出过哪些不同的问题和答案、这些答案为什么会不同”，而不仅仅是“有哪些作品涉及这个主题”。
