# 跨传统对应与关系置信度

## 1. 当前比较关系

### 《约伯记》 ↔ `Ludlul bēl nēmeqi`

当前只建立工作性判断：

```yaml
relation_type: functional_similarity
evidence_level: documented
```

理由：两个文本都形成“正直／虔敬者遭遇难以用可见罪责解释的苦难”这一高价值比较区，并都迫使叙事处理神意、报偿与人的认识限度。

现代研究也持续把 `Ludlul bēl nēmeqi` 与《约伯记》放在“义人受苦／神圣秩序与经验不一致”的比较问题域中；但这种比较首先证明的是**可比性**，不是直接文本依赖。

## 2. 两个实例为什么既相似又不能被压成同一个剧情

### 2.1 可稳定抽取的共同角色功能

| 维度 | 《约伯记》中的约伯 | `Ludlul` 中 Šubši-mēšrê-Šakkan | archetype 层判断 |
|---|---|---|---|
| 正直／虔敬身份 | 强 | 强 | core function |
| 苦难与可见罪责不成比例 | 强 | 强 | core function |
| 报偿逻辑发生危机 | 强 | 强 | core function |
| 神意／秩序难以理解 | 强 | 强 | core function |
| 身体苦难 | 强 | 强 | variable feature |
| 社会地位／关系受损 | 强 | 强 | variable feature |
| 与解释者长篇辩论 | 强 | 非核心 | Job-specific / variable |
| 公开抗议与质询 | 强 | 实现方式不同 | variable feature |
| 最终恢复 | 有 | 有 | variable feature，不设为 core |

因此 Pilot B 的抽象对象不是：

```text
“一个正直的人受苦，最后恢复”
```

而是：

```text
正直／虔敬身份
+
不成比例或难以解释的苦难
+
既有报偿解释受到压力
+
角色必须面对神圣／宇宙秩序的不透明性
```

这也解释了为什么“恢复”不能放进 `core_functions`：两个古代实例都有恢复，并不意味着所有后世受苦义人重写都必须恢复。

## 3. `Ludlul` 的差异不能被“巴比伦约伯”标签抹平

`Ludlul` 是第一人称回顾性受苦—恢复叙事，其宗教结构集中于 Marduk 的愤怒、怜悯、治愈与社会恢复。现存文本由多个泥版／残片重建，现代亚述学研究也强调其自身的书吏、祈祷、驱魔与占卜语境。

《约伯记》则把受苦问题组织成更复杂的叙事框架、诗体对话、朋友解释、约伯抗议以及神圣发言。把两者都叫“受苦义人文本”很有比较价值，但：

```text
shared problem domain
≠ same literary form
≠ same theology
≠ same source figure
```

## 4. 不直接升级为 historical_transmission

共享问题域、相近措辞或结构相似不能单独证明：

- 《约伯记》作者直接阅读了现存 `Ludlul` 版本；
- 约伯这一角色由 Šubši-mēšrê-Šakkan 直接复制；
- 两个传统只能有单一起源。

更稳妥的分层是：

```text
古代近东共享智慧／受苦问题域
→ historical_context / comparative_context

具体文本之间可观察的角色功能相似
→ functional_similarity

若未来出现足够传播证据
→ 另建 historical_transmission relation record
```

若未来研究支持传播关系，应另建：

```yaml
relation_type: historical_transmission
evidence_level: possible | probable | strongly_supported
```

不能把它与 `functional_similarity` 合并成一个字段。

## 5. archetype 比 motif 更需要防止“同名化”

两个角色都被现代研究放入“righteous/pious sufferer”问题域，不意味着：

```text
约伯 = Šubši-mēšrê-Šakkan
```

真正可以跨来源比较的是角色功能；具体人物身份、宗教语境、叙述声音、文本结构和结局解释仍留在来源层。

## 6. Pilot B 关系治理结论

当前继续支持：

```text
relation_type
+
evidence_level
+
one relation record = one relation_type
```

并新增一个 archetype 专属警告：

```text
functional abstraction
≠ historical genealogy
```

抽象原型能够由多个历史上未证明直接互相传递的实例共同支撑；这正是 archetype 与“来源谱系”不能混成一层的原因。

## 7. 研究依据入口

- Alan Lenzi, *Suffering in Babylon: Ludlul bel nemeqi and the Scholars, Ancient and Modern*：用于 `Ludlul` 文本重建、历史语境、书吏接受与受苦—恢复结构。
- Society of Biblical Literature / Job contextual studies：用于《约伯记》与古代近东“义人受苦”文本的比较，同时保留两者形式与神学差异。
- Alan Lenzi, “Reading Akkadian Prayers and Hymns” 中 `Ludlul` 选读：用于 Marduk 愤怒—怜悯、身体苦难与社会恢复的文本结构。
