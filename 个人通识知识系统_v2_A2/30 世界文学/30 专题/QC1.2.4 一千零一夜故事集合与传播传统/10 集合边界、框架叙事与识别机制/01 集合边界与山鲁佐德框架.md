# 集合边界与山鲁佐德框架

## 1. 本专题为什么不是“固定作品目录”

《一千零一夜》作为传统的稳定性，不来自一份所有版本共享的固定故事清单，而来自名称、框架叙事、长期编纂与传播实践共同维持的集合身份。

因此本专题首先区分：

```text
collection identity
≠ fixed table of contents
```

## 2. 框架叙事的组织作用

山鲁佐德通过持续讲述延缓死亡，构成整个集合最强的组织机制之一。它使一个故事可以嵌套另一个故事，也使集合能够在增加、删减与重排成员时继续保持可识别性。

所以：

```yaml
frame_narrative: true
frame_role: collection_container
```

而不是把框架简单列成普通第一篇故事。

## 3. 集合边界的三层判断

判断某材料与《一千零一夜》的关系时至少区分：

1. **传统身份层**：它是否作为《一千零一夜》整体的一部分被传抄、出版、翻译或编辑？
2. **版本成员层**：它在哪些具体 manuscript / recension / edition 中出现？
3. **独立故事层**：这个故事是否已经拥有脱离集合后的独立传播生命？

第三层若足够强，可另行评估 `story_tradition`。

## 4. 不使用“原版目录”作为默认模型

专题不预设存在一个可恢复的唯一终极目录。未来任何“核心故事”判断都必须落实到具体 witness 或可证版本传统，而不是凭现代通行版熟悉度决定。
