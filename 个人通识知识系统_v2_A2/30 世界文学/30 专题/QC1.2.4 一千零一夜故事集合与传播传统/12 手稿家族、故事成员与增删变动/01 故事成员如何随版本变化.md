# 故事成员如何随版本变化

## 1. collection_tradition 的核心单位不是固定目录

对于本专题，最重要的数据问题之一不是“故事属于不属于《一千零一夜》”这一单一布尔值，而是：

```text
story
×
collection_witness
→ membership status
```

同一故事在不同手稿、recension、印本与译本中的成员身份可能不同。

## 2. 第一轮 membership_status

```text
core_attested
→ 多个关键早期／核心见证中稳定出现

branch_attested
→ 只在特定手稿家族或 recension 中可证

translation_added
→ 经翻译／译者来源层进入该传播版本

later_print_added
→ 主要在较晚印本或编辑体系中进入集合

uncertain
→ 当前证据不足以稳定归类
```

这些状态不是价值等级，也不表示文学重要性。

## 3. membership 需要记录的字段

```yaml
story_name:
attested_in:
manuscript_family:
recension:
membership_status:
source_mode:
sequence_position:
nesting_level:
addition_removal_note:
evidence_status:
```

并非每个字段都必须立即填写；只有影响判断时才维护。

## 4. 增删不是“污染”，而是传统生命

集合传播过程中出现：

- 新故事进入；
- 某些故事退出；
- 嵌套位置改变；
- 故事被拆分或合并；
- 标题和人物名变化；
- 编辑者按目标读者重组顺序。

这些变化本身就是 `collection_tradition` 的研究对象。

## 5. 与 story_tradition 的接口

当某个成员故事脱离集合之后仍拥有持续的跨文本、跨语言、跨媒介生命时，可以从本页的 membership 记录反向触发独立 `story_tradition` 准入审查。

因此：

```text
collection member
≠ 必然只是集合内部材料
≠ 自动成为独立 story_tradition
```

是否升格仍走 QC1.2 正式准入流程。
