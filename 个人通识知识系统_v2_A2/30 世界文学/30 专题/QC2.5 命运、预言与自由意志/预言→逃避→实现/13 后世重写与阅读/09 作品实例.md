## 2. Pass B 后世作品实例

### Grimm｜《魔鬼的三根金发》

结构：

```text
贫穷男孩将娶国王女儿
→ 国王弃婴／下死亡命令／追加不可能任务
→ 男孩反复幸存
→ 婚姻预言实现
```

slot 记录：

```yaml
matched_slots:
  - authoritative_prediction
  - avoidance_action
  - predicted_outcome_fulfilled
  - renewed_avoidance_attempt
missing_slots: []
added_slots:
  - intercepted_death_letter
  - impossible_task
relation_type: structural_similarity
evidence_level: documented
```

这里不使用 `structural_inheritance`：文本足以证明结构匹配，但不足以证明该童话历史上直接继承自某个希腊来源文本。

### Pushkin｜《贤明的奥列格之歌》

结构：

```text
将因战马而死的预言
→ 奥列格把马送走
→ 多年后确认马已死
→ 查看马骨
→ 骨中之蛇咬死奥列格
```

slot 记录：

```yaml
matched_slots:
  - authoritative_prediction
  - avoidance_action
  - predicted_outcome_fulfilled
missing_slots:
  - avoidance_backfire
added_slots:
  - delayed_return_to_avoided_object
relation_type: structural_similarity
evidence_level: documented
```

这一实例非常重要，因为预言实现并不是“规避行为本身直接制造结果”，而更接近：

```text
fulfilled_despite_avoidance
```

## 3. Pass B 对 work schema 的结论

真实作品验证支持 plot-pattern 类型增加可选字段：

```yaml
matched_slots: []
missing_slots: []
added_slots: []
```

它们不是所有 QC2 组件共有的必选字段，而是 `component_type: plot_pattern` 的类型扩展。

同时 Shared Data Layer 的 `qc2_work_reference.relation_type` 需要允许：

```text
structural_similarity
```

否则会迫使没有历史继承证据的作品被错误标成 `structural_inheritance`。

## 4. structural inheritance 的治理

```text
结构高度相似
≠ structural_inheritance
```

只有当存在独立的文本、作者、改编史或传播链证据，才使用：

```text
structural_inheritance
```

若只证明作品稳定实例化同一抽象顺序，则使用：

```text
structural_similarity
```

这使 plot-pattern work reference 与 QC2 一贯的传播治理保持一致。
