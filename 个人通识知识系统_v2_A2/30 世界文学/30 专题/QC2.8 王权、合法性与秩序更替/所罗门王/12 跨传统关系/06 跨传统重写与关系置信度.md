# 跨传统重写与关系置信度

## 1. named archetype 的关键关系不是“相似人物”，而是同一命名人物的连续重写

与抽象原型不同，所罗门王的主要接受材料具有明确的人物身份连续：Solomon / Sulayman。

因此优先区分：

```text
explicit_reference
character_or_name_borrowing
figure_rewriting
direct_adaptation
```

而不是把所有关系压成 `functional_similarity`。

## 2. Pass B 正式支持 `figure_rewriting`

定义：

> 后世文本／媒介继续使用同一个可识别文化人物，并保留足够 identity anchor，但系统性重组其角色功能、故事环境或身份结构。

边界：

```text
character_or_name_borrowing
= 主要借人物／名字，不要求系统继承与重构人物功能

figure_rewriting
= 同一人物持续可识别，但角色功能／故事系统被系统重写

direct_adaptation
= 明确以某一来源故事／文本为主要整体改编对象
```

`figure_rewriting` 因此位于“借名”与“整套故事改编”之间，尤其适合 named archetype 的接受史。

## 3. 所罗门案例中的应用

### Josephus, *Antiquities* 8.42–49

保留现有：

```yaml
relation_type: explicit_reference
evidence_level: documented
```

因为当前记录的重点是明确重述并扩展 Solomon 的智慧传统；若后续需要单独记录人物功能扩展，可另建 `figure_rewriting` 原子记录。

### *Testament of Solomon*

改判：

```yaml
relation_type: figure_rewriting
evidence_level: documented
```

因为该文本不仅借用名字，而是继续把 Solomon 当作王者／智慧权威，并系统加入驱魔、控制恶魔、印章／戒指与建造工程等角色功能。

### Quranic Sulayman traditions

改判：

```yaml
relation_type: figure_rewriting
evidence_level: documented
```

共享命名人物与王权／智慧身份仍可识别，但人物进入新的经典共同体后，被重新组织为先知王，并获得对风、鸟、精灵等受神授权能力。

### *Key of Solomon* 传统

当前仍保留：

```yaml
relation_type: character_or_name_borrowing
evidence_level: documented
```

因为该传统的重要功能之一正是利用 Solomon 之名为仪式／秘传知识提供权威；若具体版本呈现更完整的所罗门人物叙事，可再单独评估 `figure_rewriting`。

## 4. 伊斯兰接受治理

```text
Hebrew Bible Solomon
→ Quranic Sulayman
```

可以确认命名人物身份连续与系统性重写，但不能写成：

```text
same narrative sequence
same theological function
same textual genealogy
```

`figure_rewriting` 正好允许“人物连续”与“语境／功能重构”同时成立。

## 5. 魔法传统治理

```text
晚期古代所罗门魔法／驱魔传统
≠ 《列王纪》已经直接描写所罗门为 grimoire magician
```

后世超自然知识、制魔、戒指／印章等属于接受史中的特征放大与新增。

## 6. 相似王者仍需另判

其他传统中的智慧王、神圣王、魔法王若没有 Solomon / Sulayman 身份连续，只能先记录：

```yaml
relation_type: functional_similarity
evidence_level: documented | similarity_only
```

除非另有独立传播证据。

## 7. Pass B 结论

```text
QC2_FIGURE_REWRITING_RELATION = SUPPORTED
QC2_FIGURE_REWRITING_SHARED_SCHEMA = READY_TO_APPLY
```

共享 relation 原子性继续保持：同一作品若同时具有 `explicit_reference` 和 `figure_rewriting`，必须拆成两条记录。
