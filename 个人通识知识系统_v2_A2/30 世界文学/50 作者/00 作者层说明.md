# 作者层说明

> 作者层是世界文学的**实体访问层**，不是 T / R / M / G / Q 之外的第六轴。

它回答的是：**如果我喜欢一个作者，如何沿着他的全部创作继续阅读？**

日常浏览直接打开：

- [[01 作者作品索引.base|作者作品索引]]：读取 `40 作品/`，按 `author` 动态分组。
- [[02 作者实体库.base|作者实体库]]：只收录已经升级为作者实体的作家。

当前已建立：[[10 作者实体/余华|余华]] · [[20 作者专题/余华/00 余华|余华专题]]

## 三层模型

```text
作品 author 字段
    ↓
Implicit Author / 隐式作者
    ↓ 产生持续追读兴趣
Author Entity / 作者实体
    ↓ 需要系统阅读、研究创作演变
Author Map / 作者专题
```

建实体就表示要追这个人。已读 / 未读看索引，不另做追读工作台。

### 1. 隐式作者

只要作品上有 `author: 某作者`，该作者就会出现在索引里。此阶段**不需要创建作者文件**。

### 2. 作者实体

明确想持续追读时，在 `50 作者/10 作者实体/` 建立实体。不手工复制作品列表；作品关系继续由 `40 作品/` 的 `author` 提供。

满足任一条件即可建实体：已读一部后想继续读；已读多部，希望集中看进度；准备建立作者专题。

```yaml
id: WL-AUTHOR-...
type: author
name: 标准作者名
aliases: []
author_map_status: 未建立 | 已建立
# 可选：birth_year / death_year / regions / movements / notes
```

覆盖率是派生指标，不把百分比写进实体：

```text
(已读 + 重读) / 当前作品库中该作者的全部收录作品
```

标准作者名用通行中文译名；英文原名写在作品的 `author_original`。模板：[[../../99 Templates/作者/01 作者实体模板|作者实体模板]]。

### 3. 作者专题

只有系统阅读一个作者的创作世界时，才在 `50 作者/20 作者专题/` 建立专题。它不是新的五轴专题，也不占用 `WL-TOPIC-*`。模板：[[../../99 Templates/作者/02 作者专题模板|作者专题模板]]。

```text
20 作者专题/<作者名>/
├─ 00 <作者名>.md
├─ 01 <作者名>.canvas
├─ 02 <作者名>作品.base
└─ 10 结构/
   ├─ 01 创作阶段.md
   ├─ 02 作品谱系.md
   ├─ 03 核心主题与母题.md
   ├─ 04 风格与叙事机制.md
   └─ 05 阅读路线.md
```

五个核心问题：创作阶段、作品谱系、核心主题、风格与机制、阅读路线。`02 <作者名>作品.base` 直接筛选 `40 作品/` 的 `author`，不要复制作品文件。

## 数据原则

1. **作品实体唯一位于 `40 作品/`。**
2. **`author` 是作品 → 作者关系的当前事实来源。**
3. **作者不是 taxonomy。** 不增加 A 轴。
4. **作者实体按需建立。** 不因为数据库里出现一个作者就批量生成作者页。
5. **作者专题按兴趣升级。**
6. **派生进度不重复存储。**
