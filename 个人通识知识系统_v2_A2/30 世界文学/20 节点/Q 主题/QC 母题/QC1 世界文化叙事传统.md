# QC1 世界叙事资源与来源传统

QC1 研究**叙事资源从哪里来，以及它们如何形成、保存、文本化、经典化、传播并获得后世生命**。

它不是“世界神话百科”，也不是把所有故事按文明装进目录；它的目标是建立一套能够从**来源文化 → 具体故事传统 → 文本见证与重写 → QC2 叙事组件**逐层追踪的叙事资源谱系。

## 1. 核心问题

QC1 主要回答四类问题：

1. 某个文化／宗教／口头传统提供了哪些重要叙事资源？
2. 某个具体故事、人物或故事循环最早如何出现，并经历了哪些文本化与重写？
3. 一个叙事资源如何跨越语言、地域、时代、文类与媒介继续流动？
4. 后世作品调用的究竟是哪一条来源谱系，而不是仅仅“看起来相似”？

## 2. 两个正式分支

```text
QC1 世界叙事资源与来源传统
│
├─ QC1.1 神话、宗教与民间叙事来源传统
│   └─ 文化／宗教／区域性的来源传统 hubs
│
└─ QC1.2 故事循环、人物传说与跨文本叙事传统
    └─ 可以追踪自身历史生命的具体 narrative traditions
```

### [[QC1.1 神话、传说与民间叙事|QC1.1 神话、宗教与民间叙事来源传统]]

回答：**“这个文化世界提供了什么叙事资源？”**

这里保存较大尺度的来源环境与叙事储备，例如希伯来—圣经、希腊—罗马、日耳曼—北欧、中国、印度、伊斯兰—波斯等传统。

研究重点包括：形成环境、宇宙观与人物系统、口传／仪式／书写机制、核心叙事群、文本化过程、内部变体、跨文化接触与后世接受。

### [[QC1.2 故事循环、人物传说与跨文本叙事传统]]

回答：**“这个具体故事／人物／故事群是怎样一路变成今天所认识的样子的？”**

这里保存具有独立文本史、传播史或重写史的具体叙事传统，例如特洛伊故事循环、亚瑟王传统、罗宾汉传统、浮士德传统等。

它填补“整个文明传统”与“抽象母题组件”之间的尺度断层。

## 3. QC1 的资源对象

QC1 可记录以下资源实体，但**不是每个实体都必须获得 QC 编号**：

| resource_type | 含义 | 默认去向 |
|---|---|---|
| source_tradition | 较稳定的文化／宗教／区域来源传统 | QC1.1 |
| narrative_cycle | 围绕共同人物、事件或世界形成的故事循环 | QC1.2 或实体层 |
| story_tradition | 一个具体故事的历时变体与文本传统 | QC1.2 或实体层 |
| figure_tradition | 围绕命名人物长期形成的叙事传统 | QC1.2 或实体层 |
| collection_tradition | 故事集、框架故事或叙事集合的形成与传播传统 | QC1.2 或实体层 |
| story_witness | 某一版本、文本见证、记录或改写 | 数据层／40 作品 |

正式编号只授予具有较高解释复用价值、足够材料和明确边界的对象；其余对象留在专题数据层或网络实体层。

## 4. QC1.1 与 QC1.2 的判定规则

```text
研究对象主要是：
“一个文化共同体／宗教／区域传统的叙事资源总库”
→ QC1.1

研究对象主要是：
“一个具体故事、人物或故事循环跨文本演变的生命史”
→ QC1.2

研究对象主要是：
“兄弟相残、英雄归乡、禁忌知识、世界树等可复用组件”
→ QC2

研究对象主要是：
“侠、骑士、武士、西部等由历史制度与社会经验组织出的文化角色世界”
→ QC3
```

同一对象可以跨层建立关系，但不复制解释内容。

## 5. 与 QC2 的接口

QC1 保存**来源与见证**；[[QC2 世界文化母题、原型与叙事结构]]保存**抽象组件及其跨文本比较**。

基本路径：

```text
QC1.1 来源传统
    ↓ contains / supplies
QC1.2 具体叙事传统
    ↓ attests / realizes
QC2 motif / tale_type / character_type / named_archetype / plot_pattern / symbol
```

允许 QC1.1 直接映射 QC2，因为某些组件并不依赖一个成熟的 QC1.2 传统；但不得因结构相似而虚构历史传播。

## 6. 建设原则

- **树负责找路，网络负责表达知识。**不要为每个神、人物或故事继续增加 taxonomy 层级。
- **优先追踪谱系，而不是罗列百科事实。**
- **文本见证优先于相似性猜测。**传播、借用与影响需要证据。
- **不按编号机械铺满。**只有真实阅读、研究和跨作品复用需求出现时才升格专题。
- **保留现有成果。**QC1.1.1—QC1.1.11 继续作为来源传统 hubs；已有专题包不因本次重构失效。
