# 奖项层说明

> 奖项层是世界文学的**实体访问层**，不是 T / R / M / G / Q 之外的第六轴，也不是文学专题。

它回答的是：**如果我认可一个奖的口味，如何沿着它的获奖作品继续阅读？**

日常浏览直接打开：

- [[01 奖项作品索引.base|奖项作品索引]]：读取已填写 `awards` 的作品，按稳定奖项 ID 动态分组。
- [[02 奖项实体库.base|奖项实体库]]：只收录 v1 目录中的奖，以及之后主动升级的奖。

## 三层模型

```text
作品 awards 字段
    ↓
Implicit Award / 隐式奖项
    ↓ 产生沿奖追读兴趣
Award Entity / 奖项实体
    ↓ 需要解释这个奖的历史、口味与偏见
Award Map / 奖项专题
```

建实体就表示要沿这个奖读。已读 / 未读看索引。

### 1. 隐式奖项

作品上只要有稳定 ID，就会出现在对应奖下。此阶段**不需要改五轴，也不需要改 `topics`**。

```yaml
awards:
  - WL-AWARD-BOOKER
```

`awards` 必须是稳定 ID 列表，用 `list.contains()` 整项匹配。不要写中文名、英文名或「布克奖 1981」这种复合字符串。

### 2. 奖项实体

奖项实体是受控目录，不是百科，也不是获奖书单。v1 只注册这 6 个作品奖：

- [[10 奖项实体/布克奖|布克奖]] `WL-AWARD-BOOKER`
- [[10 奖项实体/普利策小说奖|普利策小说奖]] `WL-AWARD-PULITZER-FICTION`
- [[10 奖项实体/茅盾文学奖|茅盾文学奖]] `WL-AWARD-MAODUN`
- [[10 奖项实体/雨果奖|雨果奖]] `WL-AWARD-HUGO`
- [[10 奖项实体/星云奖|星云奖]] `WL-AWARD-NEBULA`
- [[10 奖项实体/埃德加奖|埃德加奖]] `WL-AWARD-EDGAR`

之后只有准备沿这个奖追读、且现有 6 个奖无法表达该入口时才新增。先确认它是作品奖，不是作者生涯奖。不要因为作品库里偶然出现一个奖就批量建页。模板：[[../../99 Templates/奖项/01 奖项实体模板|奖项实体模板]]。

```yaml
id: WL-AWARD-...
type: award
name: 标准中文名
aliases: []
award_object: 作品
award_map_status: 未建立 | 已建立
# 可选：name_original / award_scope / related_topics / notes
```

`related_topics` 只表示阅读时可能对照的专题，不把获奖作品自动写入那些专题。覆盖率是派生指标，不缓存到实体。

### 3. 奖项专题

只有需要解释一个奖的历史、选评口味、争议和阅读路线时，才在 `60 奖项/20 奖项专题/` 建立专题。它不是新的五轴专题，也不占用 `WL-TOPIC-*`。把对应实体的 `award_map_status` 改为 `已建立`，再用 [[../../99 Templates/奖项/02 奖项专题模板|奖项专题模板]]。

```text
20 奖项专题/<奖项名>/
├─ 00 <奖项名>.md
├─ 01 <奖项名>.canvas
├─ 02 <奖项名>作品.base
└─ 10 结构/
   ├─ 01 边界与颁奖对象.md
   ├─ 02 历史与制度演进.md
   ├─ 03 选评口味与偏见.md
   ├─ 04 与其他奖 / 专题对照.md
   └─ 05 阅读路线.md
```

五个核心问题：边界、历史、口味、对照、阅读路线。`02 <奖项名>作品.base` 直接筛选 `awards.contains("WL-AWARD-...")`，不要复制作品文件。

## 数据原则

1. **作品实体唯一位于 `40 作品/`。**
2. **`awards` 只用稳定 ID。**
3. **奖项不是 taxonomy，也不是专题。** 得奖不自动改五轴或 `topics`。雨果奖不等于科幻专题。
4. **v1 只收录作品奖。** 诺贝尔等作者生涯奖先不进本层。
5. **按需回填，不批量灌奖。**
6. **短名单 / 年份先不建模。**
7. **派生进度不重复存储。**
