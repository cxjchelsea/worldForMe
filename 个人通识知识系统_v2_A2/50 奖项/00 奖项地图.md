# 奖项地图

> 奖项层是世界文学的**实体访问层**，不是 T / R / M / G / N / Q 之外的第七轴，也不是文学专题。

它回答的是：**如果我认可一个奖的口味，如何沿着它的获奖作品继续阅读？**

## 入口

- [[01 奖项作品索引|奖项作品索引]]：读取已填写 `awards` 的作品，按稳定奖项 ID 动态分组。
- [[02 奖项实体库|奖项实体库]]：只收录 v1 目录中的奖，以及之后主动升级的奖。
- [[10 奖项实体/00 奖项实体说明|奖项实体规则]]
- [[20 奖项专题/00 奖项专题说明|奖项专题规则]]

## 三层模型

```text
作品 awards 字段
    ↓
Implicit Award / 隐式奖项
    ↓ 产生沿奖追读兴趣
Award Entity / 奖项实体
    ↓ 需要解释这个奖的历史、口味与偏见
Award Map / 奖项专题地图
```

建实体就表示要沿这个奖读。已读 / 未读看 [[01 奖项作品索引]]，不另做追读工作台。

### 1. 隐式奖项

只要 `30 作品/` 中存在：

```yaml
awards:
  - WL-AWARD-BOOKER
```

该书就会自动出现在 [[01 奖项作品索引]] 对应奖项下。此阶段**不需要改六轴，也不需要改 `topics`**。

`awards` 必须是稳定 ID 列表，用 `list.contains()` 整项匹配。不要写中文名、英文名或「布克奖 1981」这种复合字符串。

### 2. 奖项实体

奖项实体是受控目录，不是百科。v1 只注册这 6 个作品奖：

- [[10 奖项实体/布克奖|布克奖]] `WL-AWARD-BOOKER`
- [[10 奖项实体/普利策小说奖|普利策小说奖]] `WL-AWARD-PULITZER-FICTION`
- [[10 奖项实体/茅盾文学奖|茅盾文学奖]] `WL-AWARD-MAODUN`
- [[10 奖项实体/雨果奖|雨果奖]] `WL-AWARD-HUGO`
- [[10 奖项实体/星云奖|星云奖]] `WL-AWARD-NEBULA`
- [[10 奖项实体/埃德加奖|埃德加奖]] `WL-AWARD-EDGAR`

新增奖项时先补实体与稳定 ID，再在作品上引用。不要因为某书得过目录外的奖就随手发明一个标签。

奖项实体**不手工复制获奖书单**；作品关系由 `30 作品/` 的 `awards` 提供。

奖项阅读覆盖率定义为：

```text
(已读 + 重读) / 当前作品库中 awards 含该奖 ID 的全部收录作品
```

它是**派生指标**。不把百分比写进奖项实体；以 [[01 奖项作品索引]] 的实时作品集合为准。

### 3. 奖项专题地图

只有当你希望系统理解一个奖的历史、选评口味、争议和阅读路线时，才在 `50 奖项/20 奖项专题/` 建立专题目录。

## 数据原则

1. **作品实体唯一位于 `30 作品/`。** 奖项层不复制作品实体。
2. **`awards` 是作品 → 奖项关系的当前事实来源。** 只写稳定 ID。
3. **奖项不是 taxonomy，也不是专题。** 不增加奖项轴，不创建 `WL-TOPIC-*`，不改变六轴 frozen structure。
4. **得奖不自动改六轴或专题。** 雨果奖不等于科幻专题；是否属于某专题仍由 `topics` 决定。
5. **v1 只收录作品奖。** 诺贝尔等作者生涯奖先不进本层，避免把奖写进该作者全部作品。
6. **按需回填，不批量灌奖。** 先标你要沿读的书，不为全书库补完整获奖史。
7. **短名单 / 年份先不建模。** v1 只表达“这部作品进入该奖关系”；年份与结果待多奖冲突时再升级。
8. **派生进度不重复存储。** 已收录、已读、未读和覆盖率从作品库实时读取。

## 使用方式

### 想给一本书加上奖项

在作品 frontmatter 增加：

```yaml
awards:
  - WL-AWARD-BOOKER
```

同一部书可以有多个奖。不要改 `id`、`topics`、六轴。

### 想看某个奖我还有什么没读

打开 [[01 奖项作品索引]]，按奖项查看。

### 想解释一个奖，而不只是列书

将对应奖项实体的 `award_map_status` 改为 `已建立`，再使用 [[99 Templates/奖项/02 奖项专题模板|奖项专题模板]]。
