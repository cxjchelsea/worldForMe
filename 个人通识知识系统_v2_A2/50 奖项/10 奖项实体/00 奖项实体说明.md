# 奖项实体说明

奖项实体是受控目录中的奖，不是奖项百科，也不是获奖书单。

## 什么时候建立

v1 的 6 个起步奖已经建实体，作为稳定 ID 注册。

之后只有满足以下条件才新增：

- 你准备沿这个奖追读；
- 现有 6 个奖无法表达该阅读入口；
- 先在 [[../00 奖项地图|奖项地图]] 确认它是作品奖，而不是作者生涯奖。

不要因为作品库里偶然出现一个奖就批量建页。

## 必填字段

```yaml
id: WL-AWARD-...
type: award
name: 标准中文名
aliases: []
award_object: 作品
award_status: 关注 | 追读 | 暂停 | 完成
award_map_status: 未建立 | 已建立
```

## 可选字段

```yaml
name_original: ""
award_scope: ""
related_topics: []
reading_goal: ""
notes: ""
```

`reading_goal` 只描述“为什么沿这个奖读 / 希望读到什么程度”，不维护获奖清单。

`related_topics` 只表示阅读时可能对照的专题，不把获奖作品自动写入那些专题。

## Award Reading v1

奖项追读状态由 [[../03 奖项追读工作台|奖项追读工作台]] 从 `30 作品/` 动态读取。

需要安排后续阅读时，可在**作品实体**上按需添加：

```yaml
award_reading_priority: 下一本 | 核心 | 延伸
```

该字段是个人阅读规划，不属于文学 taxonomy，不影响 `topics`、六轴、作品 ID 或专题归属。

不要批量给一个奖的全部作品填 `award_reading_priority`。

## 阅读覆盖率

覆盖率定义为：

```text
(awards 含该奖 ID，且 read_status = 已读 或 重读 的作品数)
/
(作品库中 awards 含该奖 ID 的全部收录作品数)
```

这是派生指标。v1 不将百分比缓存到奖项实体。

## 关系原则

作品列表不写进奖项实体 frontmatter。获奖作品由 `30 作品/` 中：

```yaml
awards:
  - WL-AWARD-...
```

动态反向聚合。`awards` 只用稳定 ID，不用中文名或英文名。

v1 不区分短名单、分项类别和颁奖年。一部书只需声明进入了哪个奖的关系。
