# 文学专题模板说明

## 1. 已冻结的核心原则

`literature-topic-v1` 经过 G / T / R / M / Q 与 umbrella 比较型专题的真实样板验证后，正式采用：

> **统一数据职责与知识职责，不强制目录字面完全一致。**

统一的是：
- `00` 专题首页；
- `01` Canvas；
- `02` 结构 Base；
- `03` 作品 Base；
- `10` 高层解释与导航；
- `11` 专题的第一主维度；
- `12` 可选的第二个成熟、可复用分析维度；
- `13` 仅少数专题需要的第三维（M 的转型 / 边界，T5 的文学场域）；
- `_source` 原始资料归档；
- 稳定 Topic ID、唯一作品实体和 Base 动态展示原则。

不统一的是：
- `10` 必须恰好有几页；
- `11` 必须叫什么；
- `12` / `13` 是否一定存在；
- 不同轴专题必须使用同一种认识论结构。

## 2. 目录职责合同

```text
XX 专题名称/
├─ 00 专题名称.md
├─ 01 专题名称.canvas
├─ 02 专题名称结构.base
├─ 03 专题名称作品.base
├─ 10 结构/              # 高层解释、边界、总图、桥接、阅读方法
├─ 11 [第一主维度]/      # 本专题最主要的内部拆分
├─ 12 [第二分析维度]/    # 可选；只有第二维成熟后才创建
├─ 13 [第三维]/          # 更少见；只有与 11/12 都正交时才创建
└─ _source/              # 原始资料，不承担正式数据库职责
```

### `10 结构/`

只保留高层解释和导航。通常 4–6 页即可，不要求机械凑成 5 页。

### `11 .../`

是专题最主要的第一维。它可能是：
- 时间阶段；
- 地域 / 传统入口；
- 类型史 / 亚类型；
- 叙事机制；
- 核心问题；
- umbrella 子系统。

### `12 .../`

不是“必须存在的深入专题文件夹”，而是：

> **与 `11` 不同、能够跨多个 `11` 节点重复使用的第二个成熟分析维度。**

只有同时满足以下条件时才建议建立 `12`：
1. 与 `11` 基本正交，不只是更细的同一分类；
2. 会跨多个 `11` 节点重复使用；
3. 已经需要独立解释、比较或阅读方法，而不仅是一个 Property 标签。

若不满足，继续用 Property / Base；N2 不可靠叙述已经验证：**没有 `12` 完全成立。**

### `13 .../`

不是默认层。只有同时满足以下条件才建立：
1. 与 `11`、`12` 都正交；
2. 已经需要独立解释，而不是再开一套更细的 `11`；
3. 结构 Base 能用 `dimension` 或文件夹把它从第一维里分开。

现有实例：
- M：`13 转型/` / `13 边界与转型/` / `13 内部结构/`，type 仍是 `literature_topic_section`；
- T5：`13 多极文学场域/`，type 仍是 `section`，用 `dimension: literary_field` 与 `11` 时间阶段分开。

不要为了目录对称给每个专题补 `13`，也不要为此发明新的 type。

## 3. 知识节点 type

按职责，不按文件夹编号机械映射：

| type | 用于 |
|---|---|
| `literature_topic_map` | `00` 专题首页 |
| `literature_topic_structure` | `10` 高层结构 |
| `literature_topic_section` | `11` 第一主维度；`13` 第三维 |
| `literature_topic_mechanism` | `12` 默认可复用第二维 |
| `literature_topic_network` | R 轴 `12 跨传统网络` |

## 4. 五轴知识变体

| 轴 | 第一主维度 `11` 常见形态 | 可选 `12` 常见形态 |
|---|---|---|
| T | 时间阶段 / 转折 | 跨阶段问题、世界体系、同期比较机制；T5 另有 `13` 文学场域 |
| R | 区域文学史 / 子传统 | `12 跨传统网络`；成熟者可另有 `12 区域机制` |
| M | 内部传统 / 运动入口 | 形式—经验横轴、全球化 / 殖民现代性 |
| G | 历史阶段 / 亚类型 / 类型分支 | 类型机制、trope、跨类型桥接 |
| Q | 核心问题，或成熟历史纵轴 | 跨时代问题群、尺度 / 伦理 / 记忆机制 |

N 轴（叙事技法 / 形式）已整轴撤销：不再设专题模板，作品也不再写 `axis_n`。

## 5. 与世界文学五轴的关系

每个正式专题只设置一个 `primary_anchor`。

专题层的主锚点只是**主要导航入口**，不是全部语义归属。具体作品的完整 T / R / M / G / Q 坐标继续保存在 `40 作品/` 的唯一作品实体中。

不要为了“分类完美”而：
- 复制专题；
- 复制作品；
- 新增平行五轴；
- 修改五轴底层去迁就单一专题。

## 6. 专题角色

沿用：

```yaml
topic_role: "direct"
```

用于直接锚定五轴节点的专题。

```yaml
topic_role: "umbrella"
```

用于 Q15 这类总谱系 / 比较型专题。

`00` 首页共有字段：

```text
id / type / name / primary_anchor / anchor_mode / topic_role / structure_status / work_database / structure_database
```

有 `_source` 时写 `source_archive`。QT8.1–8.8 另写 `parent_topic`。不要再加 `aliases`、`template_version`、`taxonomy_version`。

不要新增与 `primary_anchor`、`topic_role` 重复的语义字段。

## 7. Markdown / Base / Work 职责

- Markdown：定义、历史逻辑、结构解释、比较、机制、阅读方法。
- Structure Base：动态聚合专题知识节点。
- Work Base：动态聚合 `topics.contains("WL-TOPIC-...")` 的唯一作品实体。
- `40 作品/`：唯一作品实体。
- `_source/`：原始书单、旧稿、资料快照。

专题首页不维护当前作品数；数量来自 Base。

## 8. 作品字段原则

全局字段优先复用：
- `id`
- `type`
- `author`
- `read_status`
- `topics`
- `axis_t` / `axis_r` / `axis_m` / `axis_g` / `axis_q`

专题私有字段只在真正需要时增加，例如：
- `<topic>_priority`
- `<topic>_history_stage`
- `<topic>_axes`
- `<topic>_motifs`

不要给全部作品预创建所有专题字段，也不要为知识页重构而顺手重做作品 schema。

## 9. Property → Note 升格规则

```text
作品 Property / Base 标签
↓
形成稳定、可重复使用的分析关系
↓
需要独立解释 / 比较 / 阅读方法
↓
升格为 11 或 12 的知识 Note
```

原则：

> **Property 先于 Note；知识密度决定是否升格。**

## 10. 已验证样板

- G：推理、科幻、奇幻、恐怖、反乌托邦、冒险、成长、家族、历史、旅行；
- Q：爱情、战争、历史/记忆/时间；
- T：二战后多极文学；
- R：拉丁美洲文学；
- M：现代主义文学；
- N：不可靠叙述；
- umbrella：Q15 武人、英雄与秩序。

这些样板共同证明：

> **模板的稳定性来自角色合同，而不是文件夹对称。**
