# G轴专题模板：体裁 / 类型 / 叙事传统

> 核心问题：**这个类型靠什么叙事规则成立，又怎样历史地分化、混合与重写？**

## 推荐 `10 结构`

```text
10 结构/
├─ 01 定义与边界.md
├─ 02 历史演化.md
├─ 03 类型谱系与核心机制.md
├─ 04 跨类型 / 地域 / 批评桥接.md
└─ 05 阅读路线.md
```

`10` 只放高层解释页，不把所有技法、亚类型、地域和作品都堆进来。页数可按专题调整。

## 第一主维度 `11`

G轴没有唯一固定拆法。可根据专题最有解释力的第一维选择：
- 历史阶段；
- 类型分支 / 亚类型；
- 传统谱系；
- 类型发动机的主要变体。

成熟专题如果已经形成稳定的 `11 历史细分`，不为了模板整齐改成 `11 类型分支`。

每个 `11` 节点重点回答：
- 它何时、为何形成？
- 与兄弟类型 / 前驱传统的区别是什么？
- 叙事发动机和读者预期是什么？
- 哪些 trope、结构或人物模式稳定出现？
- 它怎样发生类型混合或历史转化？

## 可选第二维 `12`

当跨多个 `11` 节点重复使用的类型机制已经成熟时，可建立：

```text
12 类型机制/
```

可承载：
- 叙事发动机；
- 亚类型机制；
- trope / 结构；
- 地域传统；
- 跨类型混合；
- 批评性反类型 / 解构。

原则：Property / Base 先承载轻量分类，知识需要独立解释后再升格为 Note。

## 已验证样板

- 推理：历史纵轴 × 类型机制；
- 科幻：历史纵轴 × 子类型 / 母题 / 地域桥接；
- 奇幻、恐怖、反乌托邦、冒险：高层结构 + 历史纵轴 + 各自机制层；
- 成长、家族、历史：人物 / 社会 / 历史型小说也可使用同一职责合同；
- 旅行：历史纵轴 + 旅行机制，证明 G7 纪实传统也适用。

## G轴边界

类型专题可以与 M / N / Q 大量交叉，但不要互相吞并：
- Cyberpunk 可以同时有 G/M/Q 关系；
- 不可靠叙述属于 N，不因常见于推理就变成推理子类型；
- 爱情作为广义专题属于 Q2，不等于 Romance 类型书单。

## 不要做成

- 只有作品分类，没有类型演化解释。
- 把同一作品复制到多个专题目录。
- 因为作品跨类型就修改 G 轴底层。
- 把所有 `*_axes` 标签都立即升级成 Note。
